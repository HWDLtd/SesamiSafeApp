Application / API connection
----------------------------
The Sesami QuickStart Guide says:

1. Certificate
   All connections require the Sesami self-signed certificate to be loaded into the public trust store of the computer or mobile device connecting to the API.
   If it is not installed/trusted, the API returns an SSL certificate error.

2. Backend host and port
   The backend server host and port are configured using:
   - Operating System environment variables, or
   - environment.json

3. HTTPS
   Backend HTTPS connections use the configured serverhost/port.

4. Development ports
   In developer mode, Vite takes ownership of port 5173 and expects it to proxy to backend port 6174.

5. SignalR
   SignalR connects using the same configured serverhost/port.
   The frontend should automatically retry the SignalR connection if it disconnects.

6. Required API headers
   Backend messages require the appropriate headers:

   Content-Type: application/json
   Authorization: Bearer {token}

   For authenticated calls to non-anonymous endpoints, also include:
   UserSession: JSON.stringify(userSession)
   UserPermissions: JSON.stringify(permissions)

   The UserSession and UserPermissions objects are returned by the authentication process.
   If they are omitted where required, the backend returns not-authorized errors.

7. Swagger
   In development mode, Swagger is exposed on the configured serverhost/port under:
   /swagger

8. Startup configuration
   The environment configuration identifies the backend server host and port.
   The configuration precedence documented by Sesami is:
   - Operating System Environment Variables
   - environment.json
